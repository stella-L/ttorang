# 2026-10-07 — Supabase 백엔드 연결 작업 로그

브라우저마다 IndexedDB가 격리돼서 **파일이 유실되는 문제**를 해결하려고 Supabase를 백엔드로 붙였다. 핵심 변경: **IndexedDB를 로컬 캐시로 격하**하고 **Supabase를 source of truth**로.

---

## 1. 아키텍처 변화

### Before
```
┌─ 브라우저 ───────────────────┐
│ app.js  →  IndexedDB (전부)  │
└──────────────────────────────┘
```
- 브라우저마다 완전 격리 → 다른 Mac·Safari에선 아무것도 안 보임

### After
```
┌─ 브라우저 ────────────────┐      ┌─ Supabase (서울→일본) ──┐
│ app.js  →  하이브리드 store ◀━━▶│  tracks 테이블 (메타)   │
│          ├─ Supabase (원격)│      │  audio-files 버킷 (오디오)│
│          └─ IndexedDB(캐시)│      └──────────────────────────┘
└──────────────────────────────┘
```
- 어느 기기든 로그인 후 PIN 입력하면 같은 데이터 보임
- 네트워크 끊겨도 IndexedDB 캐시로 재생·분석 가능 (하이브리드)

---

## 2. Supabase 세팅 (시은이 직접)

1. supabase.com 가입 → `ttorang` 프로젝트 생성 (리전 `ap-northeast-1` = Tokyo)
2. SQL Editor에서 `tracks` 테이블 생성 + RLS 정책 + updated_at 트리거
3. Storage에서 `audio-files` 버킷 생성 (public, 50MB 제한)
4. `storage.objects`에 anon 접근 정책 4개(insert/select/update/delete) 추가
5. Publishable key + Project URL 확보

**주의 사항 (디버깅 시 참고)**:
- SQL Editor에서 쿼리 돌릴 때 **엔진이 `Database`인지** 확인. `Logs`(ClickHouse)로 돼있으면 `create table` 같은 Postgres 문법 다 실패하고 "Backend error"만 뜸.
- 새 쿼리 만들 때 `Create a new snippet` 선택 (Database 엔진). `Create a new logs query`는 ClickHouse라 다른 길.
- 프로젝트 생성 직후 몇 분간 백엔드 흔들림. 2-3번 Run 눌러야 통과하는 경우 많음.
- Storage는 bucket을 public으로 해도 **쓰기(upload)는 별도 RLS 정책 필요**. "new row violates row-level security policy" 에러 뜨면 대개 이 정책 미설정.

## 3. 코드 변경 요약

### `index.html`
- `<head>`에 Supabase JS SDK (UMD) + lamejs(미사용 보류) + `config.js` 로드
- `<body>` 최상단에 PIN 입력 모달 추가 (`#pin-gate`)
- `library-view`에 "⬆︎ 기존 로컬 데이터 Supabase로 올리기" 버튼 (`#migrate-btn`) + 진행률 영역(`#sync-status`)

### `app.js` 핵심 변경
- **`localStore`**: 기존 IndexedDB wrapper (이름만 변경). 로컬 캐시 역할.
- **`sb`**: Supabase 클라이언트 (`supabase.createClient(URL, KEY)`).
- **`trackToRow` / `rowToTrack`**: camelCase ↔ snake_case 변환 (JS ↔ Postgres).
- **`store`** (신규, 하이브리드):
  - `saveTrack`: 로컬 즉시 저장 → Supabase upsert
  - `saveAudio`: 로컬 캐시 즉시 → Supabase Storage 업로드
  - `allTracks`: Supabase SELECT → 로컬에도 미러. 실패 시 로컬 폴백.
  - `getAudio`: 로컬 캐시 우선. 없으면 Supabase에서 다운 후 캐시.
  - `deleteTrack`: 로컬·원격 둘 다 삭제.
- **`initPinGate`**: 로드 시 PIN 모달 띄움. localStorage에 unlock 토큰 저장(한 번만).
- **`checkMigrationNeeded` / `migrateToSupabase`**: IDB에 있지만 Supabase에 없는 트랙을 자동 감지하고 버튼 노출.
- **파일 import 플로우**: 로컬 저장 즉시 → 플레이어 열기 → 백그라운드로 Supabase 업로드 (UX).
- **`maybeCompressForUpload`**: 자동 압축 함수. 55MB에서 메모리 터져서 **당장 호출은 꺼둠** (`나중에_할일.md` 참조).

### `style.css`
- `.pin-gate`, `.pin-card`, `#pin-input` — PIN 모달 스타일
- `.migrate-btn`, `.sync-status`, `.sync-progress` — 마이그레이션 UI

### `sw.js`
- 캐시 버전 v5 → v8로 업. config.js를 ASSETS에 추가.

### `config.js` (⚠ 레포에 없음, `.gitignore`)
- Supabase URL, Publishable key, PIN, 버킷명.
- 로컬 개발용은 수동 작성, 배포는 GitHub Actions가 Secrets에서 생성.

### `config.example.js` (레포 포함)
- 템플릿. 처음 세팅할 사람이 복사해서 config.js로.

### `.github/workflows/deploy.yml` (신규)
- main 브랜치에 push되면 GitHub Pages로 자동 배포.
- GitHub Secrets(`SUPABASE_URL`, `SUPABASE_KEY`, `PIN`)에서 config.js 생성.

## 4. 삽질 로그

### 삽질 1: ClickHouse 엔진으로 쿼리 날아감
- 어제 SQL Editor에서 "Create a new logs query"를 눌렀더니 ClickHouse 엔진이 됐고 Postgres 문법 전부 fail
- "Backend error! Retry your query" 메시지만 뜨고 원인 안 보여서 삽질
- **해결**: Debug with Assistant가 "This query runs against ClickHouse"라고 알려줘서 발견. Database 엔진으로 전환.

### 삽질 2: Storage upload RLS 위반
- bucket public으로 설정했는데도 "new row violates row-level security policy" 에러
- Public이면 **읽기**만 공개. 쓰기는 별도 정책 필요.
- **해결**: `storage.objects`에 `insert/select/update/delete` 정책 4개 추가.

### 삽질 3: 자동 압축 → 브라우저 뻗음
- 55MB AAC 파일을 OfflineAudioContext로 decodeAudioData → PCM 1.3GB가 됨
- 메모리 부족으로 탭 멈춤. 에러 메시지도 없이 그냥 Hang.
- **해결**: 자동 압축 당장 OFF. ffmpeg 수동 압축으로 대체.
  ```bash
  ffmpeg -i "원본.m4a" -ac 1 -ar 24000 -b:a 64k "압축.mp3"
  ```
- 재검토는 `나중에_할일.md`에.
