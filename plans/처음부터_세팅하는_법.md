## 2. Supabase 프로젝트 만들기

### 2-1. 프로젝트 생성

1. https://supabase.com 접속 → **Start your project** → GitHub 로그인
2. **New project** 클릭:
   - **Name**: `ttorang`
   - **Database Password**: `Generate a password` → 생성된 거 메모장에 복사해둠 (쓸 일 거의 없지만)
   - **Region**: `Northeast Asia (Seoul)` 또는 `ap-northeast-1 (Tokyo)` (한국에서 빠름)
   - **Pricing**: `Free` (0.5GB DB, 1GB Storage, 2GB bandwidth)
3. **Create new project** → 1~2분 대기

### 2-2. tracks 테이블 + RLS + 트리거

프로젝트 들어가서 왼쪽 **`>_` (SQL Editor)** 클릭 → **`+ New snippet`** (⚠ `New logs query` 아님!) → 아래 복붙 → **Run**:

```sql
create table tracks (
  id uuid primary key default gen_random_uuid(),
  title text not null,
  file_name text,
  mime text,
  duration numeric default 0,
  created_at timestamptz default now(),
  updated_at timestamptz default now(),
  lyrics jsonb default '[]'::jsonb,
  memos jsonb default '[]'::jsonb,
  ab jsonb default '{"a":null,"b":null,"on":false}'::jsonb,
  repeat_all boolean default false,
  standalone_analysis jsonb,
  audio_path text
);

alter table tracks enable row level security;
create policy "allow all for anon" on tracks for all using (true) with check (true);

create or replace function set_updated_at() returns trigger as $$
begin new.updated_at = now(); return new; end;
$$ language plpgsql;

create trigger tracks_updated_at
  before update on tracks
  for each row execute function set_updated_at();
```

> **"Backend error" 뜨면**: SQL Editor 상단 **Run 왼쪽 드롭다운이 `Database`로 돼있는지** 확인. `Logs`(ClickHouse)로 돼있으면 전부 실패. 그리고 프로젝트 방금 만들어서 백엔드 흔들리면 2-3번 더 Run 눌러보기.
>
> **"Success. No rows returned"** 뜨면 OK ✅

### 2-3. Storage 버킷

왼쪽 **📁 아이콘 (Storage)** 클릭:

1. **`New bucket`** 클릭
2. **Name**: `audio-files` (하이픈 포함 정확히)
3. **Public bucket**: ✅ 체크
4. **Create bucket**

버킷 설정 (파일 크기):
1. 생성된 `audio-files` 행 hover → `⋯` → **Edit bucket**
2. **Restrict file size**: ON → `50` MB (Free 플랜 상한)
3. **Save**

### 2-4. Storage 정책 (익명 접근)

SQL Editor로 돌아가서 **`+ New snippet`** → 복붙 → **Run**:

```sql
create policy "anon upload" on storage.objects for insert to anon with check (bucket_id = 'audio-files');
create policy "anon read"   on storage.objects for select to anon using (bucket_id = 'audio-files');
create policy "anon update" on storage.objects for update to anon using (bucket_id = 'audio-files');
create policy "anon delete" on storage.objects for delete to anon using (bucket_id = 'audio-files');
```

### 2-5. URL + API Key 복사

왼쪽 **⚙ Project Settings** → **API Keys**:
- **Publishable key** (`sb_publishable_...`) 📋 복사
- **Project URL**은 Project Settings → **General** → **Project ID** 보면 `{PROJECT_ID}` 확인 가능. URL 패턴은 `https://{PROJECT_ID}.supabase.co`

> ⚠ **Secret key(`sb_secret_...`)** 는 **절대 어디에도 노출 금지**. 사용 안 함.

## 7. 자주 겪는 문제

### "Backend error" (SQL Editor)
→ 엔진이 `Database`인지 확인. `Logs`로 돼있으면 Postgres 문법 전부 실패.

### "new row violates row-level security policy" (업로드 시)
→ Storage 정책 4개 다 설정됐는지 확인. 2-4 다시 실행.

### "Payload too large" (업로드 시)
→ 파일이 50MB 넘음. ffmpeg로 미리 압축 (위 섹션 6 참조).

### Pages URL 접속해도 옛날 버전만 보임
→ 브라우저 캐시 또는 서비스 워커. F12 → Application → Clear site data.

### Actions가 실패 (빨간 X)
→ `gh run view <run-id>` 로 로그 확인. Secrets 이름 오타 가장 흔함.

### `config.js` 때문에 로컬에서 안 돌아감
→ 레포 clone 직후엔 `config.js`가 없음 (gitignore). 3번 섹션 보고 수동 생성.

## 8. 비밀번호·키 관리

| 뭐 | 어디 | 노출돼도? |
|---|---|---|
| Supabase **URL** | config.js (브라우저), GitHub Secret | 공개용, OK |
| Supabase **Publishable key** | config.js (브라우저), GitHub Secret | 공개용, OK (RLS가 지킴) |
| Supabase **Secret key** (`sb_secret_...`) | 사용 안 함 | ❌ 절대 노출 금지 |
| **PIN** | config.js (브라우저), GitHub Secret | ⚠ 노출됨. 소프트 보호만. [나중에_할일.md]에 Auth로 업그레이드 TODO 있음 |
| Supabase **DB Password** | 메모장 (안 쓰지만 분실 시 복구용) | DB 직접 접근 안 하므로 거의 안 쓰임 |

## 9. 어디서 뭘 바꿀 때 어떻게?

| 바꾸고 싶은 것 | 어디서 | 방법 |
|---|---|---|
| PIN 숫자 | GitHub Secret `PIN` + 로컬 `config.js` | Settings에서 수정 + push |
| Supabase 프로젝트 자체 | 모든 Secret + 로컬 `config.js` | 새 프로젝트 만들고 세팅 다시 |
| 기능 코드 (app.js 등) | 로컬 파일 | 수정 → commit → push → Actions 자동 배포 |
| Pages URL | GitHub Settings → Pages | 레포명 바꾸면 URL도 바뀜 (주의) |
| `sw.js` 캐시 | `sw.js`의 `CACHE` 상수 | 번호 올리고 push |
