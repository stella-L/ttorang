## 🔴 Blocking / 자주 아쉬운 것

### [ ] PIN 소프트 보안 → Supabase Auth 매직링크로 업그레이드

**현재 상황 (리스크)**: `config.js`가 브라우저로 전송되므로 사이트 접속자가 F12 열면 `PIN: '6189'` 그대로 볼 수 있음. "URL + 의지" 있는 사람에겐 뚫림.

- 노출 범위: Supabase URL, Publishable key, PIN
- Publishable key는 원래 공개용이라 OK, PIN이 문제
- 뚫리면 → 레슨 녹음·사설·분석 결과 전부 열람 가능 (삭제·추가도 가능)
- **민감도 평가**: 치명적이진 않지만 사생활·학습 콘텐츠 보호 측면에서 아쉬움

**해결 방향 (매직링크)**:
1. Supabase Dashboard → Authentication → Providers → Email magic link 활성화
2. 앱 접속 시 PIN 모달 대신 "이메일 주소" 입력 → Supabase가 이메일로 로그인 링크 전송
3. 링크 클릭 → 세션 토큰 발급 → 로컬스토리지에 저장
4. 모든 API 호출에 토큰 자동 포함 → RLS가 `auth.uid()` 기반으로 체크
5. tracks 테이블 RLS 변경: `allow all for anon` → `user_id = auth.uid()`
6. tracks 테이블에 `user_id uuid references auth.users` 컬럼 추가

**장단점**:
- ✅ 진짜 보안 (서버가 검증)
- ✅ 공유도 가능 (다른 이메일 등록해서 선생님에게도 열어줄 수 있음)
- ❌ 처음 가입할 때 이메일 인증 1회 필요
- ❌ 코드 수정 범위가 큼 (PIN 모달 → 이메일 모달, RLS 재설정, 트랙에 user_id)
- ❌ 기존 트랙에 user_id backfill 필요

**관련 코드 위치**:
- `app.js`의 `initPinGate` 함수 → `initAuthGate`로 교체
- `trackToRow` / `rowToTrack`에 `user_id` 매핑 추가
- Supabase에서 RLS 정책 재작성 (SQL 마이그레이션 하나 더)

### [ ] 큰 파일 자동 압축 재시도

**현재 상황**: 55MB m4a 파일 업로드할 때 Supabase Free 플랜 50MB 한도에 걸림.
한 번 lamejs(MP3 인코더) + OfflineAudioContext 조합으로 자동 압축을 시도했으나 **55MB 파일 디코딩 시 메모리를 1.3GB까지 쓰면서 브라우저가 뻗음**. 당장은 OFF.

**현재 대안**: 터미널에서 ffmpeg로 미리 압축 후 업로드.
```bash
ffmpeg -i "원본.m4a" -ac 1 -ar 24000 -b:a 64k "압축.mp3"
```
55MB → 약 25MB로 축소. 음질은 음성 분석엔 영향 없음.

**검토할 접근**:
1. **ffmpeg.wasm** — 브라우저 안에서 ffmpeg 실행. ~30MB 다운로드 필요. 메모리는 스트리밍이라 큰 파일도 OK.
2. **WebCodecs AudioEncoder (opus)** + webm/ogg muxer — 모던 브라우저 전용. 더 빠르고 메모리 효율적. 컨테이너 muxing 라이브러리 필요.
3. **청크 단위 디코드/인코드** — Web Audio API로는 어려움. ArrayBuffer를 수동으로 쪼개서 lamejs에 넣기? MP3 프레임 단위라 복잡.
4. **Service Worker에서 처리** — 메인 스레드 외부에서. 역시 복잡.

**관련 코드 위치**:
- `app.js`의 `maybeCompressForUpload` 함수 정의는 남아있음 (호출만 꺼둠)
- `index.html`의 `<script src=".../lamejs@1.2.1/lame.min.js">` 유지
