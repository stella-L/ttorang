# 또랑또랑 앱: 가사 자동 분석 기능 (독립 섹션)

## Context

시은은 판소리 학생으로, 선생님과의 레슨 녹음을 다시 들으며 가사의 미묘한 발음·강약·음정 표현을 배운다. 판소리 사설은 원문 그대로 발음되지 않는다 — "아버지 듣조시오"가 실제로는 "아~아 버어지 듣 쪼 시오"처럼 늘어나고, 특정 음절에서 "음이 내려가지 않게"·"강하게" 같은 발성 지시가 필요하다.

또랑또랑 앱(`~/Documents/sieun_project/korea_music`)에는 이미 **사설 탭싱크** 기능이 있지만 이건 **선생님이 풀곡을 부른 녹음**에만 쓰인다. 실제 레슨 녹음은 대화·연습·부분 시연이 섞여 있어서 탭싱크와는 별개의 흐름이 필요하다.

이 작업은 **탭싱크와 완전히 독립된 "가사 분석" 섹션**을 새로 만든다. 시은이 가사 텍스트를 붙여넣고 구간을 지정하면, 그 구간의 오디오를 분석해 (a) 실제 발음 표기로 다시 쓰고 (b) 강약·음 하강·브레스 같은 **발성 주의 문구**를 짧게 붙여준다. `glozzer.com` 같은 서비스는 수동 표기 방식인데, 여기서는 오디오 기반 자동 분석이 차별점.

> **참고**: 초기에 glozzer 표준 기호 체계(f/p/</>/비브라토/멜리스마 등)를 배지로 자동 부여하는 안을 시도했으나, 판소리 특성상 대부분의 음절에 배지가 폭발적으로 붙어 가독성이 무너져 폐기함. 지금은 **원문 발음 재작성 + 한 줄에 최대 2개 힌트**만 붙이는 심플 방식으로 회귀.

## 접근 방식

**핵심 아이디어**: 사용자가 가사 텍스트와 오디오 구간을 주면, 그 구간의 온셋·피치·RMS를 분석해 음절 단위로 특징을 뽑고, 원문을 발음 표기로 다시 쓰고 강한 신호만 힌트로 뽑아 붙인다.

자동 감지 대상은 **딱 세 가지**:

- 음절 지속시간이 중앙값 대비 배수 크면 → **판소리 스타일 늘어남 표기**
  - 받침 있음: `원(f=8) → 워~~~~~~~~~언`, `산(f=2) → 사~안`
  - 받침 없음: `아(f=3) → 아~~~아`, `버(f=2) → 버~어`, `쳐(f=3) → 쳐~~~어`
  - 틸드 개수는 factor에 비례 (`nTildes = round((factor-1)×1.3)`, 최대 15)
- 음절 RMS가 구간 중앙값의 1.5배 이상 → **인라인 강조** (`!` 접두 + 굵은 글씨)
- 음절 안에서 피치가 -120¢ 이상 하강 → `음 내려가지 않게` **회색 서브텍스트 힌트**

추가로 지속시간이 **3초 이상**인 음절 뒤에 `⟨약 4초⟩` 형태의 작은 시간 태그 인라인 표시 (0.5초 단위 반올림).

**독립 섹션이므로**:
- 자동 트리거 없음, 사용자가 "분석 시작" 눌러야 실행
- 사설 탭싱크 데이터(`lyrics[]`)를 건드리지 않음
- 여러 번 재분석 가능

## 데이터 흐름

```
사용자가 [분석 시작] 클릭
  ↓
analyzeStandalone():
  1. 오디오 blob → OfflineAudioContext → PCM (1회 디코드 후 캐시)
  2. 지정 구간 슬라이스 → RMS 곡선 계산
  3. 리딩·트레일링 무음 트림 → 실제 발화 구간 [singStart, singEnd]
  4. YIN 피치 검출, 온셋(RMS 피크) 감지
  5. 줄별 시간 범위를 음절 수 비율로 나눔
     [각 줄 시간 범위]
  6. 온셋을 시간 위치 기준으로 각 줄에 배정 (← v1과 다른 핵심 fix)
  7. 각 줄에서 음절-온셋 정렬 → 음절별 duration·meanRMS·pitchSlope 계산
  8. annotateLine(): 늘어남 표기 + 힌트 최대 2개 선정
  9. persist() → renderStandaloneAnalysis()
```

## 표기 규칙

### 발음 재작성 (판소리 스타일 늘어남)

**틸드 개수**: `nTildes = max(1, round((factor - 1) × 1.3))`, factor ≤ 1.5면 늘어남 없음, 최대 15개.

**받침 있는 음절**: `(초성+중성)` + tildes + `(ㅇ+파생모음+종성)`
- `원(ㅇ+ㅝ+ㄴ) f=8` → `워~~~~~~~~~언`
- `산(ㅅ+ㅏ+ㄴ) f=2` → `사~안`
- `관(ㄱ+ㅘ+ㄴ) f=4` → `과~~~~안`

**받침 없는 음절**: 원음절 + tildes + `(ㅇ+파생모음)`
- `아(ㅇ+ㅏ) f=3` → `아~~~아`
- `버(ㅂ+ㅓ) f=2` → `버~어`
- `쳐(ㅊ+ㅕ) f=3` → `쳐~~~어`  (ㅕ의 파생 ㅓ)
- `삐(ㅃ+ㅣ) f=2` → `삐~이`

**파생 모음 매핑** (이중/복합모음의 후반부만 뽑음):
- 단순 모음(ㅏㅑㅐㅔㅗㅜㅡㅣ 등): 유지
- ㅝ→ㅓ, ㅘ→ㅏ, ㅙ→ㅐ, ㅚ→ㅣ, ㅞ→ㅔ, ㅟ→ㅣ, ㅢ→ㅣ
- ㅕ→ㅓ, ㅑ→ㅏ, ㅛ→ㅗ, ㅠ→ㅜ

### 인라인 강조 (RMS 피크 음절 1개)

`f-scale > 1.5` 인 음절에 `!` 접두 + 굵은 글씨. 예: `!사안`. 별도 힌트 서브텍스트로 표시하지 않음.

### 시간 태그 (3초 이상 음절)

지속시간 3초↑ 음절 뒤에 `⟨약 N초⟩` 인라인 작은 태그 (0.5초 단위 반올림).
- 4.2초 → `⟨약 4초⟩`
- 3.4초 → `⟨약 3.5초⟩`

### 서브텍스트 힌트 (줄당 최대 2개)

| 조건 | 힌트 |
|---|---|
| 음절 내 피치 -120¢ 이상 하강 | `N음절: 음 내려가지 않게` |

강하게는 인라인으로 이동해서 서브텍스트에 안 나온다.

## 데이터 구조

`tracks` 스토어에 신규 필드:
```js
track.standaloneAnalysis = {
  inputText: "원산의 해가 아니 삐쳤더니",
  segment: { mode: 'ab' | 'full' | 'custom', startSec, endSec },
  showAnnotated: true,          // 원문/분석 토글 상태
  results: [
    {
      i: 0,
      original: "원산의 해가",
      tokens: [
        { text: "워~~~~~~~~~언", accent: false, durationSec: 4.2 },
        { text: "사안", accent: true,  durationSec: 0.8 },
        { text: "의",   accent: false, durationSec: 0.3 },
        { text: "해",   accent: false, durationSec: 0.5 },
        { text: "가",   accent: false, durationSec: 0.4 }
      ],
      hints: ["3음절: 음 내려가지 않게"]
    }
  ],
  analyzedAt: 1727401234567
}
```

렌더러는 `token.accent`면 `!` + `<strong.syl-accent>`, `token.durationSec >= 3`이면 `<span.syl-duration>⟨약 N초⟩</span>` 붙임. 기존 저장 데이터에 `tokens`가 없고 `annotated`만 있으면 문자열 그대로 폴백.

기존 트랙은 이 필드가 없음 → 읽을 때 `?? null`로 안전 처리 (마이그레이션 불필요).

## 수정 파일

### `index.html`
- 사설 섹션 아래 `<section id="analysis-section">` 추가
- textarea, 구간 라디오 3개(`full`·`ab`·`custom`), 시각 입력, 분석 시작 버튼, 결과 영역, 로딩 스피너

### `app.js` (~450줄 추가)
자체 구현 YIN 피치 검출 (외부 라이브러리 zero) + 온셋·브레스·시간기반 온셋 분포 + 한글 음절 늘어남 표기.

주요 함수:
- `decodeAudioToBuffer(blob)` — OfflineAudioContext 1회 디코드, 트랙 단위 캐시
- `toMono` / `sliceMono` — 채널 병합 후 시간 범위 슬라이스
- `computeRMSContour(pcm)` — 프레임 2048/홉 512로 에너지 곡선
- `trimSilence(rms, sr, offset)` — 리딩·트레일링 무음 잘라 실제 발화 구간 찾기
- `detectOnsets(rms, sr, offset)` — 국소 최대 RMS 피크, 80ms 최소 간격
- `yinPitch(frame, sr)` — YIN 알고리즘 직접 구현 (~50줄)
- `detectPitchContour(pcm, sr)` — 무음 프레임 스킵 + YIN (16kHz 다운샘플)
- `splitKoreanSyllables(text)` — 공백·문장부호 제거 후 문자 단위 배열
- `decomposeHangul(char)` / `composeHangul(cho, jung, jong)` — 유니코드 자모 분해·조립
- `SECOND_VOWEL_MAP` — 중성 인덱스 → 파생 모음 인덱스 (이중/복합모음 후반부 추출)
- `computeTildeCount(factor)` — factor에 비례한 틸드 개수 (최대 15)
- `elongateSyllable(char, factor)` — 판소리 스타일 늘어남 (받침 분리 규칙 포함)
- `distributeOnsetsToLines(onsets, lineTimeRanges)` — **시간 위치 기준 배정**
- `computeLineBoundaries` / `computeSyllableFeatures` — 음절 경계와 특징
- `annotateLine(syllables, feats, medians)` — `tokens[]` + 힌트 배열 반환
- `analyzeStandalone()` — 파이프라인 조율, result에 `tokens` 저장
- `renderStandaloneAnalysis()` — 결과 렌더 (원문/분석 토글, 서브텍스트 힌트)
- `renderTokens(container, tokens)` — 토큰별 DOM 생성 (`.syl-accent` 강조, `.syl-duration` 시간 태그)

### `style.css`
- `#analysis-section` — 사설 섹션과 구분
- `.result-line` — 각 줄의 분석 결과 카드
- `.result-text` — 재작성된 가사 (본문 크기)
- `.result-hints` — 회색 서브텍스트, `↳` 화살표, 다중 힌트는 `·`로 구분
- `.syl-accent` — 강조 음절(`!` 접두)에 accent 색 + 굵은 글씨
- `.syl-duration` — 3초↑ 음절 뒤에 붙는 작은 회색 태그(`⟨약 4초⟩`)
- `.analysis-loading` — 스피너

## 재사용 자산

- IndexedDB `audio` 스토어의 blob — 분석 원본
- `persist()` 저장 파이프라인 — track 객체 전체 저장하므로 신규 필드 자동 포함
- A-B 마커 상태 — 구간 지정에 재사용
- `fmt(sec)` mm:ss 유틸

- [ ] 기존 트랙이 정상 로드되고 재생·A-B 반복·배속·사설 탭싱크·메모 동작 유지

- [ ] 3초 이상 음절 뒤에 `⟨약 X초⟩` 인라인 태그가 붙음
- [ ] `음 내려가지 않게` 힌트만 회색 서브텍스트로 남음 (강하게는 인라인으로 이동)
- [ ] [원문/분석 토글]로 원본 텍스트 ↔ 분석 결과 스위칭
- [ ] [초기화]로 결과·입력 클리어
- [ ] 앱 재실행 시 저장된 분석이 트랙에 복원됨
- [ ] 오프라인에서 이미 분석된 트랙 결과 정상 표시
- [ ] 사설 섹션의 탭싱크·편집이 분석 섹션과 완전히 분리됨
